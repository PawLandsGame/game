# Инструкции для работы с PawLands

## Рабочие деревья

- Перед началом каждой отдельной задачи создай отдельный Git worktree и ветку от целевой ветки. Выполняй изменения, проверки и коммит задачи в этом worktree.
- Если пользователь не указал целевую ветку, используй текущую ветку основного рабочего дерева.

## Коммиты и публикация

- После проверки каждой завершённой задачи создай отдельный коммит и сразу отправь его в целевую ветку `origin`. Обновляй целевую ветку только с сохранением её истории. Не объединяй независимые задачи в один коммит.
- Подписывай каждый коммит. Если автоматическая подпись отключена, используй `git commit -S`. Перед публикацией проверяй наличие подписи.
- Используй формат Conventional Commits `тип(область): описание`. Область необязательна. Тип пиши стандартным английским токеном (`feat`, `fix`, `docs`, `chore`), а описание и тело коммита пиши на русском языке.
- Включай в коммит только изменения, относящиеся к задаче. Если пользователь указал другую ветку или попросил отложить публикацию, следуй его указанию.

Пример: `fix(клиент): дождаться подключения перед входом в игру`.
